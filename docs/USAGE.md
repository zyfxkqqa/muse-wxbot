# 使用

## 聊天

直接在微信里给机器人发消息就行：

- 文字：直接回。
- 图片：能看。
- 语音：有转写文字，也能转出来听。
- 视频 / 文件：能打开看。

回复是简短的微信风格。复杂的事、要翻主聊记录的事，机器人做不了，得回主聊那边。

## 对话指令

单独发一条纯文字（整句匹配）即执行，不会当成普通聊天：

| 指令 | 作用 |
|---|---|
| 帮助 / `/帮助` / `help` | 看指令清单 |
| 新建对话 | 归档当前对话、开一个空的新对话（这才是真的清掉上下文，旧的留着能切回） |
| 切换对话 | 看对话清单（一页 10 条，编号按创建顺序固定），下方带翻页与切换提示 |
| 下一页 / 上一页 | 对话清单翻页 |
| 切换到 数字（空格可有可无，如「切换到 1」「切换到1」） | 切换到指定对话 |
| 修改旁聊名称 新名字 | 给当前对话改名，只回「已改名。」 |

新建对话只回「已开始新对话。」；改名只回「已改名。」；指令回复只发固定文案，不加解释。

## 绑定介绍

- 绑定微信第一次发消息：worker 先发介绍、再回问题，两条连续一前一后，只发一次。
- 没有新人欢迎：机器人只跟绑定的那个微信号说话，陌生人加不上机器人好友，所以不存在“新联系人第一次发消息”这个场景。

介绍的文案见 hook 的 worker 指令配置 `hooks/wechat-inbox.json`。

## 多机器人

- 每个机器人绑一个不同的微信号，各自有独立的对话历史。
- 给哪个机器人发消息，就是哪个机器人回，不会串。
- 对话清单、切换、改名等都是按当前这个机器人自己的对话来的。

## 查看器（viewer/）

网页查看器，和 CLI 是一体的：读同一份历史文件，还能在页面里回消息、发媒体、暂停自动回复。

- 源码与重建方法：`viewer/`，说明见 [viewer/README.md](../viewer/README.md)。
- 打开方式：在 Muse 侧边栏打开「微信机器人会话查看」。
- 用法：选机器人 → 选对话 → 看全部历史。支持关键词搜索（只搜当前打开的对话，高亮、逐条跳转）、手动同步与实时刷新（每 8 秒自动同步）、给机器人加备注、未读数与「从新消息开始看」（点开有未读的对话直接定位第一条未读；滑到底即标已读、清零）。
- 回消息：在对话页底部输入框发文字（最多 2000 字），回形针按钮发图片/视频/语音；暂停按钮按机器人+联系人暂停自动回复，暂停时只记不回、由用户在页面里手动回。
- 新绑定的机器人不用改代码，会自动出现在列表里。
- 查看器自己的数据库只存备注与已读条数，不存消息内容；它的 `app.db` 不入库。
